# helios-naryady

Распознавание бумажных заказ-нарядов зуботехнической лаборатории по фото с телефона.

Лаборант фотографирует рукописный наряд и отправляет его Telegram-боту. Через 15–30 секунд
приходит ответ, а в Google Таблице появляется строка. Если с нарядом что-то не так,
бот так и пишет и называет причину:

```
⚠️ Наряд №106 — на проверку
• итого 21000 ≠ сумма строк 20000
Улыбка+ · Петрова А.В. · пациент Фёдоров В.Н.
21 000 ₽, сдача 30.10
```

## Как это работает

```
фото ──► image.prepare ──► Extractor.extract ──► checks.check ──► sheets.write ──► ответ в Telegram
         EXIF, поиск листа,   Claude vision +       сумма, зубы FDI,   строка «ОК» или
         перспектива, сжатие  строгая схема         цвет VITA, даты,   «На проверку» + причины
                              (pydantic Naryad)     справочник клиник
```

Принцип: **схема достаёт данные без потерь, проверки решают, можно ли им верить.**
Модель записывает то, что написано на бланке, даже если там ошибка (например, неверный итог).
Ошибку ловят проверки, и наряд уходит человеку. Остальные поля при этом не теряются.

| Модуль | Отвечает за |
|---|---|
| `schema.py` | Что модель обязана вернуть. Все поля обязательные, но могут быть `null`: «поля нет» говорится явно |
| `image.py` | Поворот по EXIF, поиск листа (Otsu → контур → 4 угла), выравнивание перспективы, JPEG |
| `prompt.py` | Системный промпт: правила чтения бланка и справочник клиник и врачей |
| `extractors.py` | Вызов Claude: Messages API + structured outputs. Протокол `Extractor` позволяет подменить модель в тестах |
| `checks.py` | Можно ли пустить наряд в таблицу без человека |
| `sheets.py` | Google Таблица: листы «Наряды» и «Работы», идемпотентная запись |
| `pipeline.py` | Одно фото → таблица. Общий шаг для консоли и бота |
| `bot.py` | Telegram-бот (aiogram): доступ по списку id, сохранение оригиналов, ответ со статусом |
| `evaluation.py`, `compare.py` | Прогон на эталонах, метрики, кэш ответов модели |
| `cli.py` | Команды `naryad eval`, `crop`, `process`, `bot` |

### Таблица

- **«Наряды»**: строка на наряд. Колонка «Статус» принимает значения `ОК` или `На проверку`, в колонке «Причины» — почему.
- **«Работы»**: строка на работу, связь с нарядом через колонку «Ключ».

Правила записи:
- повторная отправка **того же фото** обновляет строку, дубль не появляется;
- **тот же номер с другого фото** записывается отдельной строкой «на проверку»: молча перезаписать чужой наряд нельзя;
- строку, у которой человек поставил статус `Проверено`, программа больше не трогает.

### Бот

- Доступ только по списку Telegram id. Чужому пользователю бот отвечает «нет доступа» и показывает его id, чтобы его можно было добавить.
- Оригинал фото сохраняется в `data/inbox/<дата>/` до распознавания. При сбое API или Google фото не теряется, его можно обработать позже через `naryad process`.
- До 3 фото распознаются параллельно, а запись в таблицу идёт строго по одной, чтобы не было гонки.

## Качество

Проверено на 9 рукописных нарядах с эталонами. В набор специально включены ошибки в итоге,
неуверенный почерк, заполнение карандашом и формула зубов крестом.

| Модель | Точность по 12 полям | На проверку | Тихие ошибки |
|---|---|---|---|
| Claude Opus 5.5 | 99% | 4/9 | 0 |
| Claude Sonnet 5.5 | 99% | 4/9 | 0 |
| Claude Haiku 5.5 (без обрезки) | 96% | 9/9 | — |

**Тихая ошибка** — это наряд со статусом «ОК», в котором есть неверное поле. Это главная метрика:
такие ошибки попадают в таблицу незамеченными. У обеих старших моделей их 0, все ошибки
распознавания ушли на проверку.

Ограничения оценки. 9 нарядов — это мало, разница в одно поле здесь укладывается в шум.
Все бланки написаны одной рукой. На этом же наборе настраивался промпт. Честную цифру даст
отдельный набор новых нарядов, лучше разными почерками.

## Запуск

```
python -m venv .venv
.venv\Scripts\activate            # Linux/macOS: source .venv/bin/activate
pip install -e ".[dev]"
copy .env.example .env            # заполнить, см. ниже
```

| Переменная | Где взять |
|---|---|
| `ANTHROPIC_API_KEY` | [console.anthropic.com](https://console.anthropic.com) |
| `GOOGLE_CREDENTIALS_FILE` | Google Cloud: сервисный аккаунт с включённым Google Sheets API → ключ JSON → положить в `secrets/` |
| `GOOGLE_SHEET_ID` | Часть ссылки на таблицу между `/d/` и `/edit`. Таблицей нужно поделиться с email сервисного аккаунта с правами «Редактор» |
| `TELEGRAM_BOT_TOKEN` | @BotFather → `/newbot` |
| `TELEGRAM_ALLOWED_IDS` | Telegram id через запятую. Свой id бот покажет в ответ на `/start` |

```
naryad bot                                    # Telegram-бот
naryad process фото1.jpg фото2.jpg            # то же без бота: фото → таблица
naryad eval                                   # прогон на эталонах: точность, на проверку, тихие ошибки, $
naryad eval --model claude-sonnet-5-5 --fresh
naryad crop                                   # обрезанные фото → results/crops, проверить глазами
pytest && ruff check src tests
```

По умолчанию используется модель `claude-opus-5-5`, другую можно указать флагом `--model`.

Данные для оценки: фото в `data/photos/naryad_NN.jpg` (в git не попадают), эталоны в
`data/truth/naryad_NN.json`, справочник клиник в `data/clients.json`. Все имена, клиники
и суммы в репозитории вымышленные.

Ответы модели при оценке кэшируются в `results/<модель>/<отпечаток>/`. Отпечаток — это хэш
промпта, схемы, версии обработки фото и модели. Поэтому правка проверок пересчитывается
бесплатно, а после правки промпта старые ответы не подхватятся. Флаг `--fresh` распознаёт заново.
